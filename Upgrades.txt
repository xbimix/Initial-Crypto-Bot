## Phase 1 — Stabilize Architecture (Critical Refactor)

**Acceptance:**

* No file should exceed ~500 lines.

## Phase 2 — Upgrade Paper Execution (High Priority)

### 2. Replace naive fill model

**Task:**

* Implement realistic execution simulation.

**Steps:**

1. Add:

   * Fee model per exchange (taker/maker).
   * Slippage model based on spread & depth.
   * Partial fills & rejection scenarios.
   * Latency simulation.
2. Use existing snapshot fields (`spread_bps`, `imbalance`, `microprice`) to model fill price.
3. Update paper broker to record:

   * expected vs. actual fill price
   * slippage
   * fees
   * latency

**Acceptance:**

* Every simulated trade includes fee, slippage, latency, and partial fill probability.

## Phase 3 — Improve Risk Management (High Priority)

### 3. Implement stop-based sizing

**Task:**
Replace `position_size()` logic.

**Steps:**

1. Define:

   ```
   risk_per_trade = account_balance * risk_percent
   stop_distance = abs(entry_price - stop_price)
   size = risk_per_trade / (stop_distance + fees + slippage)
   ```
2. Cap final size by:

   * max position
   * max notional
   * per-asset exposure
3. Fail trade if computed size < minimum tradable.

**Acceptance:**

* Position size always tied to actual loss risk.

## Phase 4 — Strengthen Regime & Routing (Medium Priority)

### 4. Turn routing into measurable system

   * confidence score
2. Track route performance:

   * win rate
   * drawdown
3. Periodically evaluate route performance and demote poor routes.

**Acceptance:**

* Route performance measurable and auditable.
